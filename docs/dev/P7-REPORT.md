## Addendum — S3-F1 fix (post-review)

The independent P7 review (`~/workspace/udvasito-work/qa/p7-pr-review.md`, APPROVE WITH NOTES) found **S3-F1**: `admin.settings.update` validated numbers, booleans, strings and the two feature-flag maps, but every other object/array-valued setting (`noShowPenalty`, `waveSizes`, `quietHours`, `waveIntervalMin`, `stillComingAfterMin`, `ai.models`, `ai.limits`, `verification`, `medicalReviewer`, `pilotDistrictIds`) fell through with no check — the reviewer's probe stored `noShowPenalty ← "garbage"`, `waveSizes ← 42` and `quietHours ← true`, all accepted. The slice-10 wording above originally read "VAL-19 range/type checks from SETTING_DEFS", which overstated the coverage for these keys; it has been corrected.

**Fix commit:** `3ffbe49` — "P7 fix: validate object/array settings in admin.settings.update (S3-F1)".

**What changed:**
- `convex/admin/settings.ts`: a recursive `validateShape()` now runs for every remaining object/array default, before any write. An object value must carry exactly the default's fields (all required, no unknown fields) with matching primitive types at every depth; array elements must match the default's element type; numbers must be finite; strings obey the existing 500-char cap. A refused update throws `ERR_VALIDATION`, stores nothing and writes no audit row; valid updates audit exactly as before.
- `convex/_lib/settingsData.ts`: SETTING_DEFS gains data-driven rule metadata taken from specs §5.2 — `fieldRules` (`waveIntervalMin` each 1–120, `stillComingAfterMin` each 5–120, `quietHours` start/end in HH:mm format, `noShowPenalty` count 1–10 / days 30–180), `elementRange` (`waveSizes` each 1–200), and `elementType` (`pilotDistrictIds` = string; its default array is empty, so the element type cannot be inferred from a default element).

**Test evidence:** new regression test "F-904/S3-F1: object/array settings are shape-validated, nothing stored on failure" in `tests/p7.test.ts` — the reviewer's three probes now reject with `ERR_VALIDATION`, as do a nested wrong type (`noShowPenalty.count: "two"`, `ai.limits.liteDaily: "500"`), wrong-typed array elements (`waveSizes: [10, "25", 50]`, `pilotDistrictIds: [123]`), a missing field, an extra field, an unknown key, out-of-range fields and a bad HH:mm value; refused attempts leave the stored defaults untouched and produce zero `setting_changed` audit rows; valid object/array updates (`noShowPenalty`, `waveSizes`, `pilotDistrictIds`, `quietHours`) succeed, persist and audit (4 rows), and a later refused attempt leaves the stored valid value intact. Full gate after the fix: **`npm run check` green — tsc clean, eslint 0 errors, 413/413 tests (28 files)** — the 412 pre-fix tests all still pass, plus the one new regression test.
